## 4. Hypothetical, backtested and simulated performance

- **Library and reports.** OpenFactsheet never generates simulated or backtested
  results. It analyzes the series it is given and cannot verify whether that
  series is an actual track record, a model portfolio, a backtest or pro-forma
  data. `DISCLAIMER.md` therefore states that backtested, simulated, modeled or
  hypothetical results are not actual trading records. Reports show the input
  provenance (source type, observation count, window, frequency) so the user can
  label their own data.
- **Repository fixtures and examples.** Synthetic, and documented as such in
  `scripts/make_fixtures.py` and `THIRD_PARTY_NOTICES.md`. The README's
  hedge-fund example describes the fixture as a fixture "shaped like" a
  hedge-fund track record, not as a real fund.
- **Website.** The demo series is labelled "Synthetic sample fund … not a real
  fund or a real pitch" at the display location (observed 2026-10-16). The
  educational pages discuss simulated records as a topic but were not observed
  to present a simulated track record as performance.
- **CFTC 4.41 / NFA 2-29 text.** Not inserted. Applicability has not been
  established, and the prescribed text must not be paraphrased. Decision for
  counsel: whether any page (for example an analysis of a user-supplied CTA
  series, or a future "example CTA" demo) requires it.

files on 2026-10-16 (`*.md`, `*.cff`, `*.toml`, `*.typ`) for: `guarantee`,
`safe`, `risk-free`, `riskless`, `SEC-approved` / `SEC approved` /
`SEC compliant` / `SEC registered`, `FCA-compliant` / `FCA approved`,
`fully audited` / `security audited`, `highest return(s)`, `best fund`,
`certified`, `endorse`.

| Term | Repository result |
| :-- | :-- |
| guarantee | 3 technical uses: decision 0007 ("one engine guarantees that every drawdown metric describes the same path"), decision 0010 ("the `<=` rule guarantees a non-empty tail"), and `docs/reference/criteria.md` ("no guarantee of future performance"). None is a performance promise. New disclaimer text says accuracy is *not* guaranteed |
| safe / safely | None (apart from the new disclaimer's "not a regulatory safe harbor") |
| risk-free | 80+ uses, all the technical "risk-free rate" convention (0% in methodology 0.1.0), plus the new CONTRIBUTING rule that forbids "risk-free" as a promotional claim |
| riskless, SEC-approved/compliant/registered, FCA-compliant/approved, fully audited, security audited, highest returns, best fund, certified | None |
| endorse | Only in new non-endorsement statements (README creator section, attribution, notices) |

Website (public pages fetched 2026-10-16: home, about, demo, legal, fair-factsheet,

## 7. Software maturity: public alpha

Searched case-insensitively for `beta` / `alpha` in the README, documentation,
changelog, `pyproject.toml`, `CITATION.cff`, the manual source and badges. The
only `beta` occurrences in the repository are the statistical coefficient (beta,
bull/bear beta) and code identifiers; none refers to software maturity, so
nothing was renamed. The README already said "Status: alpha (methodology
0.1.0)" before this change and the classifier is `Development Status :: 3 -
Alpha`; both are kept. The README now reads "**Status: Public alpha** ·
Methodology 0.1.0" with the caution "Public alpha: interfaces, metrics and
documentation may evolve; validate results before investment decisions." The
package version is not changed here and is not bumped to 1.0.0. No security
audit claim is made. The website's "private beta" wording (§3) is the remaining
inconsistency. Unrelated to maturity: the README's metric-count badge says 90
while the text says 97; the metric count is maintained with the metric work.
